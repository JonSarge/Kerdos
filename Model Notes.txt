The case for binary win/loss:
  The fundamental problem with the current setup is that the 4-class model is simultaneously learning to distinguish Win/Place/Unplaced/OOM, but you then discard all that and just use .pred_Win. The model's gradient updates during training are pulled in multiple directions, with most signal going toward correctly classifying the dominant Out_of_Money class. A binary model concentrates all learning capacity on the one boundary that actually matters.
  XGBoost also has a native solution for binary imbalance: scale_pos_weight, set to the ratio of negatives to positives per race. For a 10-runner field with 1 winner, that's roughly 9. This is cleaner than SMOTE and computationally free.

The case for keeping multiclass:
  The placement positions (2nd, 3rd) do carry some real information — a horse that consistently finishes 2nd has a meaningfully different profile than one that runs last. In theory, the multiclass structure can capture this. In practice, for XGBoost with noisy real-world racing data, the gain is probably marginal.
